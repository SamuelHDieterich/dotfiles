# Alembic migrations

Alembic lives next to the models it reflects. `env.py` must import the models package for its side effect, so metadata is populated before autogenerate runs:

```python
import mypkg_db  # noqa: F401

target_metadata = SQLModel.metadata
```

A model that isn't reachable from that import is invisible to autogenerate. Its table silently never appears — and worse, an existing table can be autogenerated as a *drop*. When a new model produces an empty migration, or an unrelated table shows up as removed, check the package exports before believing the diff.

## Autogenerate is a draft

Read every generated migration before running it. It reliably misses server defaults, index and constraint renames, `CHECK` constraints and enum value changes. Reviewing the output is the step that makes the tool safe, not optional diligence on top of it.

Name the revision after the schema change, not the feature it serves — the filename is what someone reads while debugging a failed upgrade.

## Running

Check before upgrading, every time:

```console
$ alembic current
$ alembic upgrade head --sql    # review the SQL
$ alembic upgrade head
```

Projects usually wrap this in a script because production runs through a proxy and needs specific extras. Prefer the project's script over calling `alembic` directly — it encodes connection details you would otherwise have to guess.

Against production, produce the plan and hand it over. Applying it is not yours to do.

## Writing them by hand

Give every migration a working `downgrade`. A "not implemented" downgrade turns a bad deploy into a restore-from-backup.

Keep schema changes and data backfills in separate revisions. A schema step that fails halfway leaves a table half-altered; a backfill that fails halfway leaves rows half-written. You want to re-run one without the other.

Adding a non-nullable column to a populated table takes three revisions: add it nullable, backfill, then set `NOT NULL`.

## Verifying

A migration test that "probably passed" has not passed. If the check ran in the background, wait for it and read the output before reporting. Quote the result.
